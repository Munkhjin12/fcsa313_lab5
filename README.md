## 1. Сонголт ба төлөөлөх утгын хүснэгт

| # | Сонголт | Эквивалент анги | Төлөөлөх утга |
|---|---------|-----------------|---------------|
| 1 | studentID-гийн хүчинтэй байдал | идэвхтэй | `status: "active"` |
|   |  | идэвхгүй | `status: "inactive"` |
|   |  | байхгүй | PUT хийгээгүй ID (`S02_GHOST`) |
| 2 | Оюутны үзсэн хичээлүүд | урьдачийг хангана | `coursesTaken: ["CS201"]` |
|   |  | урьдачийг хангахгүй | `coursesTaken: []` |
| 3 | courseID-гийн хүчинтэй байдал | байгаа | PUT хийсэн ID |
|   |  | байхгүй | PUT хийгээгүй ID (`C04_GHOST`) |
| 4 | Хичээлийн урьдач нөхцөл | бүгд үзсэн | `["CS201"]` ↔ `["CS201"]` |
|   |  | огт үзээгүй | `["CS201"]` ↔ `[]` |
|   |  | зарим нь | `["CS201","CS202"]` ↔ `["CS201"]` |
|   |  | урьдачгүй (хязгаар) | `[]` |
| 5 | Хүсэлтийн формат | бүрэн | studentID + courseID хоёулаа |
|   |  | талбар дутуу | studentID эсвэл courseID байхгүй |
|   |  | буруу JSON | бүтэц нь эвдэрсэн бие |

**Боломжгүй хослол:** оюутан байхгүй бол "үзсэн хичээл" гэсэн сонголт утгагүй; хичээл байхгүй бол "урьдач нөхцөл" утгагүй. Иймд эдгээр хослолыг тусад нь ангилж, харгалзах алдааны тестээр л хамарсан. Мөн талбар дутуу эсвэл буруу JSON үед оюутан/хичээлийн сонголтууд огт үнэлэгдэхгүй (хүсэлт эртхэн татгалзагдана).

## 2. Спецификацийн хүснэгт

| ID | Спецификаци | Хүлээгдэх статус | Хүлээгдэх result |
|----|-------------|------------------|------------------|
| T01 | Happy path: идэвхтэй оюутан, урьдач хангана | 201 | `OK` (+ registrationID тоо) |
| T02 | Оюутан байхгүй | 200 | `ERROR_NO_STUDENT` |
| T03 | Оюутан идэвхгүй | 200 | `ERROR_INACTIVE_STUDENT` |
| T04 | Хичээл байхгүй | 200 | `ERROR_NO_COURSE` |
| T05 | Урьдач огт хангахгүй | 200 | `ERROR_PREREQUISITES`, missing=`["CS201"]` |
| T06 | Урьдач зарим нь хангагдсан | 200 | `ERROR_PREREQUISITES`, missing=`["CS202"]` |
| T07 | Давхар алдаа: оюутан ч, хичээл ч байхгүй | 200 | `ERROR_NO_STUDENT` |
| T08 | Давхар алдаа: идэвхгүй оюутан + урьдач дутуу | 200 | `ERROR_INACTIVE_STUDENT` |
| T09 | Хязгаар: урьдачгүй хичээл, хоосон coursesTaken | 201 | `OK` (+ registrationID тоо) |
| T10 | Хязгаар: courseID талбар дутуу | 400 | `ERROR_BAD_REQUEST` |
| T11 | Хязгаар: studentID талбар дутуу | 400 | `ERROR_BAD_REQUEST` |
| T12 | Хязгаар: буруу JSON | 400 | `ERROR_BAD_JSON` |

T07, T08-ын хүлээлтийг серверийн жинхэнэ ажиллагаагаар баталгаажуулсан: `server.js` нь оюутны шалгалтыг хичээлийнхээс, идэвхтэй эсэх шалгалтыг урьдачийнхаас түрүүлж хийдэг.

Тест бүр өөрийн ID-тай (`S01_HAPPY`, `C05_NOPRE` …) setup PUT-аа өөрөө хийдэг тул бие даасан. registrationID-ийн яг утгыг шалгаагүй, зөвхөн тоо мөн эсэхийг шалгана. Тестийн нэр нь шалгаж буй зүйлээ шууд хэлнэ (ж: "Идэвхгүй оюутан бүртгүүлэхэд ERROR_INACTIVE_STUDENT").

## 3. Newman-ы ажиллуулалт

```bash
mkdir -p results
newman run lab05-collection.json 2>&1 | tee results/newman-pass.txt
echo "exit=$pipestatus[1]"          # zsh; bash: ${PIPESTATUS[0]}
```

| Ажиллуулалт | Файл | Exit code | requests executed / failed | assertions executed | assertions failed |
|-------------|------|-----------|----------------------------|---------------------|-------------------|
| PASS | `results/newman-pass.txt` | 0 | 26 / 0 | 42 | 0 |
| FAIL | `results/newman-fail.txt` | 1 | 26 / 0 | 42 | 2 |
| DOWN | `results/newman-down.txt` | 1 | 26 / 26 | 42 | 42 |

Collection дахь тестийн тоо: 12 тест (T01–T12), нийт **42 assertion** (setup PUT-ын статус шалгалтууд орно).

**PASS.** Сервер ажиллаж байхад бүх 42 assertion давсан, exit code 0.

**FAIL.** `lab05-collection-fail.json` нь үндсэн collection-той яг ижил, зөвхөн хоёр happy-path тестийн (T01, T09) хүлээгдэх статусыг 201-ээс 200 болгож зориуд буруу oracle тавьсан. Сервер зөв 201 буцаасан тул 2 assertion унаж, exit code 1 болсон. Үндсэн `lab05-collection.json` өөрчлөгдөөгүй. Exit code 0 / 1 нь CI quality gate-ийн зарчим: тест унавал pipeline зогсоно.

**DOWN.** Серверийг унтрааж (`Ctrl+C`) ажиллуулахад бүх 26 хүсэлт `connect ECONNREFUSED 127.0.0.1:3000`-аар унасан, exit code 1.

**Интерфейсийн алдаа ба oracle-ийн алдааны ялгаа:** ECONNREFUSED үед хүсэлт серверт огт хүрээгүй тул хариу байхгүй (assertion-ууд `expected undefined` гэж унасан) — энэ нь холболт/интерфейсийн алдаа, харин FAIL ажиллуулалтад сервер хариу өгсөн боловч хариу нь хүлээлтээс (201 ≠ 200) зөрсөн нь oracle-ийн алдаа.

## 4. Дүгнэлт

Дизайны 5 алхмаас хамгийн их бодол шаардсан нь "төлөөлөх утга" ба "спецификаци" болгон хослуулах алхам байлаа, учир нь сонголтуудын бүх хослолыг бичих боломжгүй тул аль хослолыг сонгохоо шийдэх хэрэгтэй болсон. Боломжгүй хослол таарсан: оюутан байхгүй үед түүний үзсэн хичээлийн сонголт утгагүй, хичээл байхгүй үед урьдач нөхцөл утгагүй тул тэдгээрийг тусад нь ангилсан. Давхар алдааны хослолд заавар аль алдааг түрүүлж буцаахыг заагаагүй тул T07, T08-аар сервер дээр туршиж баталгаажууллаа: оюутан байхгүй бол хичээлийн шалгалтаас өмнө `ERROR_NO_STUDENT`, идэвхгүй оюутан урьдач дутуутай бол `ERROR_INACTIVE_STUDENT` түрүүлж буцна. Тестүүд серверт ямар нэг согог олсонгүй: 42 assertion бүгд давсан, тиймээс энэ нь серверийн хариу спецификацтай нийцэж байгааг л харуулна, согоггүй гэсэн баталгаа биш. Тест бүр өөрийн setup-тай, өвөрмөц ID-тай учир дарааллаас хамаарахгүй бөгөөд registrationID-ийн яг утгыг шалгаагүй тул дахин ажиллуулахад тогтвортой. FAIL ажиллуулалт нь oracle зөв ажиллаж байгааг, assertion унахад exit code 1 болдгийг харуулсан. DOWN ажиллуулалт нь серверийн алдаа ба холболтын алдаа өөр зүйл гэдгийг ойлгуулсан: 26 хүсэлт бүгд errored болж, assertion-ууд хариугүйгээс унасан. Гар аргаар Postman дээр дарахаас Newman-аар командын мөрөөс ажиллуулах нь давтагдах, CI-д холбогдох боломжтой тул илүү найдвартай.
